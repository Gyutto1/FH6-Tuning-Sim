## 3. Run 的 tag 存在哪里？

**两个位置（不一致风险）：**

1. `runs_index.json` → `tags: []` + `intent_tags: []` 数组（存储 tag_key 字符串）
2. `annotations.json` → 通过 `annotation_store.upsert_annotation()` 存储（target_type="run", target_id=session_id, tag_ids=[...])

当前所有 run 的 tags/intent_tags 均为空，annotations.json 也不存在。添加 tag 时需要**同时写入两处**或**优先使用 annotation layer**。

## 6. 目前是否能区分系统标签和用户标签？

✅ 已实现。系统标签在 `configs/dictionaries/`，用户标签在 `data/index/tags.json`。`tag_library_page` 和 `record_run_page` 已合并读取。

## 7. 当前筛选函数是否基于标准字段筛选？

✅ 刚刚实现的 `filter_run_records()` 基于标准化 record 字段筛选（car_id, route_mode, record_type, tag_keys, quality_status, keyword）。

## 8. 当前 UI 是否只是显示数据，没有保存能力？

- Run Library：**仅显示**，无编辑/归档按钮
- Tag Library：**可创建**用户标签
- Car Detail：**可编辑**车辆信息
- Record Run：**仅表单**，不写入

**Run 级编辑（notes, tags, archive）完全缺失。**

## 10. 最小安全修复方案

### 方案：tags 存入 runs_index.json + 注解层同步

1. `add_tag_to_run(session_id, tag_key)` → 更新 runs_index.json 的 tags 数组 + 同步写 annotations.json
2. `remove_tag_from_run(session_id, tag_key)` → 同上
3. `update_run_notes(session_id, notes)` → 更新 runs_index.json 的 notes 字段
4. `archive_run(session_id)` → 设置 `is_active: false`, `status: "archived"`
5. 所有写操作前自动 `.bak.{timestamp}` 备份

### Run Library UI 新增：

- 每条 run 卡片下方：标签 chips + [编辑] [归档] 按钮
- 编辑模式：修改备注、添加/移除标签
- 归档确认对话框："归档此记录？归档后默认列表中不显示，但数据不会删除。"
